# Аудит исходного состояния Sultan Trade — 17.11.2026

Проверен реальный main репозитория dontcallme112/sultan_trade перед изменениями. Это статический аудит и доступные локальные проверки, не проверка работающих production сервисов.

- Frontend: React 19, Vite 7, React Router 6. Магазин содержит каталог, товар, корзину, оформление, профиль, OAuth callback. Тендерных маршрутов не было.
- Backend: Express 4, axios, Supabase service role, Upstash Redis. al-style вызывается сервером, присутствуют кеширование, очередь запросов, mutex заказов, периодическая синхронизация каталога, Telegram уведомления при наличии настроек. Реальную доступность al-style/Redis/Telegram без учётных данных подтвердить нельзя.
- Авторизация: Supabase AuthContext уже есть; сервер проверяет getUser. Её переиспользуем, добавляя отдельные роли тендерного модуля, чтобы не давать всем покупателям доступ руководителя.
- Backend не запускается без ALSTYLE_ACCESS_TOKEN. Это сохранено для магазина; новый отдельный локальный demo backend не требует токена поставщика.
- Frontend supabaseClient создаётся при загрузке и требует переменных окружения. Для локальной демонстрации документированы фиктивные loopback значения; для магазина нужен dev Supabase.
- README содержал `<<<<<<< HEAD` и `=======`, устаревшее описание LUXE и инструкцию VITE_ALSTYLE_ACCESS_TOKEN. README заменён актуальной краткой инструкцией; секреты поставщика не следует помещать в VITE_*.
- Vercel перенаправляет все пути на index.html; Express размещается отдельно. Для /tenders используется существующий backend URL. Production размещение не менялось.
- ALLOWED_ORIGINS при отсутствии настройки разрешает любые origin. Перед staging задайте точные адреса frontend. Это существующее поведение магазина, в рамках MVP не изменено.
- В исходном backend есть гостевой notify-order; он может отправлять Telegram при наличии credentials и ограничен по частоте. Полный аудит всех маршрутов магазина и финансовых операций остаётся отдельной задачей.
- В репозитории нет оформленного набора миграций существующей БД, который доказывал бы текущие RLS/права production. Новые ti_* таблицы изолированы, RLS включён, клиентские grants отозваны. Миграция не применялась к рабочей базе.
- Исходная команда lint использовала флаг --ext с flat config и общий конфиг относит backend к browser globals. Проверки старого проекта могут иметь много существующих замечаний; новые файлы проверяются отдельно. Команда lint обновлена под flat config.

Повторно используемые части: Router/layout, Supabase Auth, apiClient/BACKEND_URL, существующая серверная авторизация провайдера и архитектура Express. Интернет-магазин не переписывался, каталог/заказы/цены не изменялись. Этапы OCR/AI, финансы, Stockera-связь и расширенная автоматизация не входят в этот MVP.

После настройки Node globals для backend/Vite общий lint показывает 48 замечаний старого кода (43 errors, 5 warnings). Новые файлы проходят целевую проверку. При браузерной проверке исправлено горизонтальное переполнение существующего footer на 390px: колонка и поле подписки теперь могут сжиматься. Основные маршруты магазина сохраняются; реальные покупки и поставщик не тестировались без учётных данных.
