# Подготовка подключения к 1С:Бухгалтерия для Казахстана

Этап: проверка файлового обмена, без подключения к информационной базе.
Это собственный формат пакета анализа тендеров. Он не является стандартной
загрузкой 1С, CommerceML, счётом, заказом, накладной или проводкой.

## Что уже доступно

- Защищённый GET /api/tenders/onec/package.json с фильтрами каталога, до 200 строк,
  включая остальные страницы. Вход сотрудника обязателен; sync-secret недостаточно.
- UTF-8 JSON, schema v1; денежные значения — строки с двумя десятичными знаками,
  неизвестные значения — null. Валюта бюджета и валюта финансового анализа раздельны.
- preparedByUserId указывает автора личного финансового среза. Перед загрузкой
  согласовать, чьи расчёты используются; не смешивать срезы разных сотрудников.
- externalKey сохраняет связь с исходным лотом; contentHash помогает определить
  изменение содержания. Это SHA-256, не цифровая подпись и не защита от подмены.
- Модуль reader.bsl выполняет только структурную проверку JSON, версии, режима
  и повторных ключей в одном пакете. Он не создаёт объекты и не проводит документы.
  Код требует проверки в тестовой 1С: платформа 1С в среде разработки отсутствует.
- package.schema.json описывает формат для разработчика обработки. Перед записью
  в 1С нужна полная проверка полей и хеша, а не только проверка reader.bsl.

## Порядок подключения на тестовой копии

1. Зафиксировать версию платформы, релиз конфигурации и доработки базы.
2. Сделать резервную копию и отдельную тестовую информационную базу.
3. Разработчик 1С размещает reader.bsl в общем модуле/внешней обработке и проверяет
   вызов ПроверитьПакетSultanTrade(ПутьКФайлу). Ожидаемый результат — ТолькоПроверка.
4. Сопоставить организацию, контрагента по БИН, номенклатуру и единицу измерения.
   null и неоднозначные совпадения требуют ручного выбора, без автосоздания.
5. С бухгалтером определить документ/регистр назначения, валюту и правила НДС.
   Пользовательские ставки калькулятора не превращать автоматически в реквизиты 1С.
6. Отдельно реализовать обработку записи черновиков: реестр обработанных externalKey
   и contentHash, транзакция, отчёт ошибок, повторная загрузка без дублей.
7. Проверить на копии: повторный файл, изменённая строка, неизвестный БИН,
   отсутствующая валюта/единица, групповой лот, отказ прав и откат ошибки.
8. Подключение к действующей базе и проведение согласуются отдельно.

## Матрица сопоставления

| Поле пакета | Назначение в 1С | Правило |
|---|---|---|
| externalKey | Внешний идентификатор обмена | Хранить связь, не искать только по названию |
| customer.bin / name | Контрагент | БИН проверять; при отсутствии — ручное сопоставление |
| accountingMapping.organizationRef | Организация | Выбирается в конкретной базе |
| accountingMapping.nomenclatureRef | Номенклатура | Лот не равен товару; групповой лот требует разбора |
| unit / quantity | Единица и количество | Проверить упаковку и коэффициент пересчёта |
| referenceBudget | Бюджет тендера | Справочная сумма, не сумма документа |
| analysis | Финансовое планирование | Не проводки и не подтверждение налогового учёта |

Не размещайте логин/пароль 1С в браузере или JSON. Прямой HTTP/OData-обмен пока
не включён; адреса, реквизиты метаданных и способы аутентификации не угадываются.
